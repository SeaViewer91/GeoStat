# 공간통계학 자습서 구성안 v1

가제: **처음 만나는 공간통계학** — GeoStat으로 따라 하는

## 1. 목표와 원칙

- 도구 설명서가 아니라 **공간통계학이라는 학문 전체를 처음부터 이어서 설명하는 한 권의 책**임. GeoStat은 책의 실습 도구 역할을 함
- 목표 상태: **공간통계를 쓴 논문의 방법 절을 읽고 무엇을 왜 했는지 판단할 수 있고, 자기 연구에서 방법을 고르고 근거를 대고 보고할 수 있는 상태**
- 앱이 지원하지 않는 분야(점 패턴, 지구통계, 스캔 통계, 베이지안 공간 모형 등)도 다룸. 학문의 지도는 앱의 기능 목록보다 넓어야 함
- 수식을 피하지 않음. 대신 모든 개념을 **직관 → 작은 예제 손계산 → 일반식** 순서로 설명하고, 식이 나오면 말로 한 번 더 풀어 씀
- 증명은 대부분 생략하고 **시뮬레이션**으로 보여 줌. 참 구조를 알고 만든 자료에 방법을 돌려서, 그 방법이 무엇을 찾고 무엇을 놓치는지 직접 확인하게 함
- 문체는 음슴체(~음, ~함, ~임). README·앱 문체와 같음
- 방법마다 원전과 역사를 짧게 소개함. 학문을 보급하려면 방법이 어디서 왔는지, 누가 어떤 문제를 풀려고 만들었는지까지 전해야 함

## 2. 독자와 전제 지식

- 대상: 공간정보·지리학 비전공 연구자, 실무자, 대학원생 (보건·역학, 도시계획, 부동산, 환경·생태, 수산·해양, 사회과학, 원격탐사 응용)
- 전제: 고교 수학, 기초 통계 한 학기 정도(평균·분산·회귀를 들어 본 수준). 부족하면 2부로 보충함
- 행렬은 6부(공간 회귀)부터 본격적으로 씀. 필요한 만큼만 부록 B에 정리함

## 4. 강의 틀 (모든 강 공통)

1. **이 강에서 얻는 것**: 학습 목표 3개
2. **들어가는 질문**: 이 강의 방법이 필요해지는 연구 질문 하나 (예: "이 지역에 암 발생이 몰려 있다는 민원, 우연인가?")
3. **본문**: 절 3~6개. 직관 → 작은 예제 손계산 → 일반식 → 가정과 성질
   - 필요한 곳에 **이 방법은 어디서 왔나** 상자 (원전, 연도, 당시 풀려던 문제)
4. **시뮬레이션으로 보기**: 참 구조를 아는 자료에서 방법이 어떻게 동작하는지 확인함 (해당하는 강만)
5. **해 보기**: 앱 지원 강은 **GeoStat에서** (샘플, 메뉴 경로, 설정값, 기대 결과 수치), 미지원 강은 **코드로** (Python, PySAL 계열. GeoStat 엔진과 같은 라이브러리)
6. **헷갈리는 쌍**: 1~3쌍 (예: LISA HH ↔ Gi* 핫스팟, 공간시차 ↔ 공간오차)
7. **흔한 실수와 심사 지적**: 비전공자가 실제로 틀리는 지점과 심사위원이 묻는 질문, 그리고 대응
8. **보고서에는 이렇게 씀**: 방법 절에 넣을 문장 예시 (가중치, 순열 횟수, 보정 방법, 유의수준 등 적어야 할 항목)
9. **요약**: 5줄
10. **핵심 용어**: 한글, 영문, 도구별 명칭 (GeoDa, ArcGIS, PySAL, R)
11. **원전과 더 읽을거리**: 원전 1~3편과 표준 교과서의 해당 장
12. **연습**: 3~5문항. 손계산 1개 이상, 해 보기 1개 이상. 일부 해답은 부록에 둠

그림은 스크립트로 그리는 SVG. 강당 2~4개, 전체 약 130개 예상.

## 5. 예제 자료

### 가상 지역 "한빛시" (책 전체를 관통)

- 한국형 가상 도시 하나를 만들어 대부분의 강에서 같은 지리로 이어 씀. 좌표계 EPSG:5186
- 1강 기준 확정 사항: 인구 120만 명, 면적 454 ㎢, 구 5개(가람·누리·다솜·라온·마루), 행정동 150개. 실제 지형과 겹치지 않게 서해 바다 위(동경 125.0~125.4°)에 둠. 파일은 레이어마다 따로 둠(GeoStat이 한 번에 레이어 하나씩 열기 때문)
- 구성 요소마다 난수 흐름을 따로 써서, 나중에 변수를 더해도 이미 책에 쓴 값이 바뀌지 않게 함. 책에 쓴 구성 요소의 규칙은 고치지 않음
- **모든 변수를 알려진 확률 과정으로 생성**하고 시드를 고정함. 참 구조를 알기 때문에 "이 방법이 참을 찾아내는가"를 보여 줄 수 있음. 실제 자료로는 불가능한, 교과서만의 장점임
  - 예: 계수가 일정한 자료에 GWR을 돌리면 지역 차이가 얼마나 거짓으로 생기는지, 무작위 자료에서 LISA가 몇 %를 유의하다고 찍는지
- 구성

| 레이어 | 형태 | 쓰는 강 |
|---|---|---|
| 행정동 약 150개 | 폴리곤. 도심은 작고 외곽은 크게 (MAUP·면적 편향 시연) | 1·3·6·7·8부 |
| 500 m 격자 | 폴리곤 | 3강(MAUP), 11부 |
| 사건 점 | 군집 점 과정 (인구 밀도에 비례 + 국지 군집) | 4부, 14·15강 |
| 관측소 약 60개 | 점. 가우시안 확률장 표본 | 5부 |
| 고도·지표온도 | 래스터 | 4·20·40강 |
| 연도별 패널 (10년) | 행정동 × 연도 | 9부 |

- 생성 스크립트 `book/data/make_hanbit.py`, 변수별 참 모형은 부록 G에 **참 모형 카드**로 공개함 (책을 다 읽은 뒤 맞혀 보는 재미)
- 자료 파일은 `book/data/`에 GeoPackage로 두고, 독자가 내려받아 GeoStat으로 엶 (앱 번들 샘플에 추가할지는 나중에 판단)
- **손계산용 초소형 자료**: 3×3 격자, 5×5 격자, 점 10개처럼 본문 손계산 예제를 그대로 GeoJSON으로도 넣음. "손으로 0.53, 앱에서도 0.53"을 확인하게 함

### 고전 공개 자료 (원전 수치 대조용)

- 원전이나 교과서에 나온 수치와 독자가 직접 맞춰 볼 수 있게 함
- 후보: NC SIDS(비율·ESDA, 앱 번들), 조지아(GWR, 앱 번들), Columbus 범죄(공간 회귀, Anselin 1988), Meuse(지구통계), 점 패턴 고전 자료 1종
- **라이선스 확인 후 사용**. 번들하지 못하면 내려받는 방법만 안내함

### 한국 공개 자료

- 연습문제의 과제로만 씀 (통계청 SGIS, 공공데이터포털 등). 경계가 해마다 바뀌고 공공누리 유형이 제각각이라 번들하지 않고 출처와 받는 방법만 적음

## 6. 강 목록

표기: 강 번호 · 제목 [앱 지원] — 다루는 내용

### 0부 들어가며
- **0강 공간통계학이란 무엇인가** [-] — 일반 통계와 무엇이 다른가(공간 의존성, 공간 이질성), 토블러의 제1법칙, 세 갈래(면 자료·점 패턴·연속 표면)와 공간계량경제·지역 회귀, 짧은 역사(Moran 1950 → Matheron → Cliff & Ord → Ripley → Anselin → Fotheringham), 이 책을 읽는 법, GeoStat 소개

### 1부 공간 자료
- **1강 공간 자료의 세 얼굴** [●] — 벡터·래스터, 점·선·면, 속성과 지오메트리. Cressie의 세 유형(연속 표면, 면 자료, 점 패턴)과 각 유형이 이어지는 방법. 같은 현상도 어떻게 기록하느냐에 따라 분석이 달라짐
- **2강 좌표계와 거리** [●] — 지리·투영 좌표계, EPSG, 한국 좌표계(5186·5179·5174), 거리·면적 왜곡, 대권거리, 경위도로 거리를 재면 생기는 문제
- **3강 척도와 단위의 문제** [◐] — MAUP(척도 효과·구획 효과), 생태학적 오류(Robinson 1950), 지원(support), 변하는 분모. 한빛시를 행정동과 격자로 집계하면 상관이 어떻게 바뀌는지 시연
- **4강 공간 자료 준비** [●] — 공간 결합, 점 집계, 존 통계, 격자화, 경계 효과, 결측과 섬, 품질 점검
- **5강 지도로 탐색하기** [●] — 단계구분도 분류법(분위수·등간격·Jenks·표준편차·박스 지도), 색 체계, 면적 편향(큰 면이 눈을 지배함), 카토그램, 연동 시각화(linked brushing)와 탐색적 자료 분석

### 2부 통계 다시 보기
공간 맥락에서 필요한 만큼만 압축함. 예제는 모두 한빛시.
- **6강 요약·분포·추정** [◐] — 요약통계, 분포, 표준오차, 신뢰구간, 부트스트랩
- **7강 검정의 논리와 순열 검정** [◐] — p값의 뜻, 1·2종 오류, **순열·무작위화 추론**(공간통계 검정의 기본 도구), 다중검정(FWER·FDR, 본페로니·BH)
- **8강 회귀분석과 진단** [●] — OLS, 가정과 잔차 진단, 이분산, 다중공선성, 변수 변환, 최대우도, AIC·AICc
- **9강 독립 가정이 깨질 때** [○] — 유효 표본 크기, 의사반복, 자기상관 자료에서 t검정의 1종 오류율이 얼마나 부풀려지는지 시뮬레이션. 2부와 3부를 잇는 다리

### 3부 공간 자기상관
- **10강 이웃 정하기: 공간가중치** [●] — 인접(룩·퀸·고차), 거리 기준, KNN, 커널, 역거리. 표준화(이진·행·분산 안정), 섬과 연결성, 비대칭 가중치, 선택 기준과 민감도 분석
- **11강 전역 공간 자기상관** [◐] — Moran's I(Moran 1950), Geary's C(Geary 1954), General G. 세 가지 추론(정규 가정·무작위화·순열), 모란 산점도, 거리 구간별 코렐로그램, 결과가 가중치에 따라 달라지는 폭
- **12강 국지 공간 자기상관 I: LISA** [●] — Anselin 1995, 국지 Moran, 조건부 순열, 네 사분면(HH·LL·HL·LH), 유의성 지도와 군집 지도의 차이, 다중검정과 보정, 경계 효과, "LISA는 군집의 핵을 찍을 뿐 경계를 긋지 않음"
- **13강 국지 공간 자기상관 II** [◐] — Gi·Gi*(Getis & Ord 1992, Ord & Getis 1995), Local Geary와 다변량 Local Geary(Anselin 2019), 이변량 Moran과 그 함정(Lee's L), 범주 자료의 Join Count(전역·국지). "핫스팟 분석"이라는 이름이 도구마다 가리키는 것
- **14강 비율 자료와 작은 수 문제** [●] — 원비율, 초과위험·SMR, 분모가 작을 때의 분산 불안정, EB 평활(Clayton & Kaldor 1987)과 공간 EB, EB Moran(Assunção & Reis 1999). 지도에서 가장 튀는 곳이 가장 작은 지역인 이유
- **15강 공간 군집 탐지** [○] — Kulldorff 공간 스캔 통계(1997), 군집 탐지·자기상관 검정·핫스팟 분석이 각각 답하는 질문의 차이, 민원형 질문("여기 몰려 있다")을 다루는 법과 사후 가설의 함정

### 4부 점 패턴
- **16강 점 패턴의 기초** [○] — 완전 공간 무작위(CSR)와 포아송 과정, 강도, 1차·2차 성질, 관찰창과 경계 효과, "점이 어디 있는가"와 "점에 붙은 값"의 구분
- **17강 강도 추정** [◐] — 방격법(격자 만들기 + 점 집계로 가능), 커널 밀도 추정과 대역폭 선택, 상대 위험 지도(사례/대조 밀도 비), 공변량에 따라 달라지는 강도
- **18강 점 사이의 상호작용** [○] — 최근린 거리(G·F 함수), Ripley's K(1976)·L 함수, 쌍상관함수, 모의 포락선 검정, 불균질 K, 교차 K와 표시 점 패턴
- **19강 점 과정 모형** [○] — 불균질 포아송 모형, 군집 과정(Thomas, Neyman-Scott), 억제 과정(Strauss), 로그 가우시안 콕스 과정 개요. 모형 적합과 진단

### 5부 지구통계
- **20강 연속 표면과 확률장** [○] — 정상성(2차·내재), 등방성, 지원. 결정론적 보간(티센, IDW, 스플라인)과 그 한계. 왜 "불확실성까지 주는 보간"이 필요한가
- **21강 베리오그램** [○] — 실험 베리오그램, 너깃·문턱값·상관거리, 모형(구형·지수·가우시안·마테른)과 적합, 이방성, 코렐로그램과의 관계
- **22강 크리깅** [○] — Krige와 Matheron. 단순·정규·보편 크리깅, 크리깅 분산, 교차검증, 회귀 크리깅, 코크리깅, 블록 크리깅(지원 변경)
- **23강 불확실성과 시뮬레이션** [○] — 조건부 시뮬레이션, 지시 크리깅과 초과 확률 지도, 크리깅 분산을 이용한 표본 배치

### 6부 공간 회귀
- **24강 왜 공간 회귀인가** [●] — OLS 잔차 자기상관의 결과(편의인가 비효율인가), 공간 의존의 두 원천(실질적 파급 vs 오차의 성가신 의존), 잔차 Moran's I, LM 검정과 Anselin의 모형 선택 흐름

## 7. 앱 지원 표시와 기능 로드맵

- 강 머리말에 `app: full | partial | code`를 적고, 본문 맨 위에 배지로 보여 줌
- ○·◐ 강은 **GeoStat 기능 로드맵의 후보 목록**이기도 함. 코드형 강을 쓸 때마다 앱에 넣을지 판단함 (예: 코렐로그램, 커널 밀도, Ripley's K, 베리오그램·크리깅, 스캔 통계, SLX·SDM)
- 앱에 기능이 들어가면 해당 강의 "코드로"를 "GeoStat에서"로 바꾸고 배지를 갱신함
- 책이 앱을 끌고 가는 구조임. 앱의 기능 목록에 맞춰 학문을 자르지 않음

## 8. 용어 원칙

- 공간통계 한국어 용어는 문헌마다 다름. 책의 용어집을 하나의 기준안으로 삼음
- 원칙
  - 앱 UI 표기와 책 표기를 같게 함
  - 첫 등장에 영문과 주요 이형을 병기함
  - 용어집 `book/glossary.json`에 권장어, 이형, 영문, 도구별 명칭을 두고 lint로 이형 사용을 경고함
- 확정이 필요한 용어 예
  - spatial lag: 공간시차 / 공간지연 / 공간래그
  - spatial weights matrix: 공간가중치 행렬 / 공간가중행렬
  - GWR: 지리가중회귀 / 지리적 가중 회귀
  - MAUP: 가변적 공간 단위 문제 / 가변 면적 단위 문제
  - (semi)variogram: 베리오그램·세미베리오그램 / 배리오그램 / 반변동도
  - LISA: 국지적 공간연관 지표 / 국지 공간 자기상관 지표

## 9. 형식, 배포, 깨짐 방지

책은 **앱에 내장하지 않고 GitHub 저장소의 md 파일로만 관리함**. 독자는 github.com에서 바로 읽거나, 내려받아 md 뷰어로 읽음. 따라서 **GitHub의 마크다운 렌더링이 곧 책의 조판**이며, 모든 형식 규칙은 GitHub에서 깨지지 않는 것을 기준으로 정함.

**원본**
- `book/README.md`: 책 표지 겸 목차. 부·강 목록(링크), 읽는 길, 앱 지원 배지 설명, 내려받아 읽는 법, 진행 현황
- `book/lessons/<강번호>-<영문 슬러그>.md` (예: `10-spatial-weights.md`, 부록은 `A-method-map.md`). 파일 목록만 보고도 내용을 알 수 있게 함. 한글 파일명은 내려받기·URL에서 깨지기 쉬워 쓰지 않음
- 머리말(YAML): id, part, title, app, version, updated, status. GitHub는 머리말을 표로 보여 주므로 짧게 유지함
- 강마다 맨 위와 맨 아래에 **이전 강 · 목차 · 다음 강** 링크를 둠. 스크립트로 생성하고 lint로 점검함
- `book/parts.json`, `book/glossary.json`
- 그림 `book/fig/<강번호>-<이름>.svg`, 그림 스크립트 `book/fig-src/`
- 자료와 생성 스크립트 `book/data/`
- **기대 수치** `book/expected.json`: "해 보기"에 나오는 결과 수치를 모아 둠. 엔진 테스트가 이 파일로 결과를 검증하고, lint는 본문 수치와 이 파일을 대조함. 앱 버전이 바뀌어도 책과 결과가 어긋나지 않게 함

**수식 (GitHub 수식 렌더링 기준)**
- 블록 수식은 `$$`를 **앞뒤 빈 줄을 둔 단독 줄**에 씀. GitHub와 오프라인 뷰어(VS Code 미리보기, Obsidian, Typora) 모두에서 읽힘
- 인라인은 `$...$`. 안에 `_`, `*`, `\\`, `{}`처럼 마크다운과 부딪히는 문자가 있어 깨지면 `` $`...`$ `` 형식으로 씀 (GitHub 전용 표기라 lint가 목록으로 관리함)
- 표 안에서는 `|` 대신 `\vert`, `\lvert`, `\rvert`
- 사용자 정의 매크로(`\newcommand`) 쓰지 않음
- 본문에 달러 기호를 쓰지 않음

**한글과 굵게**
- GitHub(CommonMark)는 `**구역 통계(zonal statistics)**라고`처럼 닫는 `**` 앞이 문장부호이고 뒤에 한글이 바로 붙으면 굵게가 적용되지 않음. VisionDrill은 앱 렌더러에서 고쳤지만 GitHub에서는 고칠 수 없음
- 규칙: 괄호·따옴표로 끝나는 굵게 뒤에 조사를 바로 붙이지 않음. 문장을 바꾸거나 `<strong>…</strong>`을 씀. lint가 이 패턴을 잡음

**그림**
- 도식은 SVG를 이미지 링크(`![캡션](../fig/10-rook-queen.svg)`)로 넣음. 본문에 SVG를 직접 넣으면 GitHub가 지우므로 쓰지 않음
- VisionDrill 그림 규칙을 따름: 색은 클래스로만 지정하고 SVG 안의 `prefers-color-scheme`으로 다크 모드 대응, `id` 금지, viewBox, 캡션 필수. 배경은 투명하게 두지 않고 명시함 (GitHub 테마와 OS 설정이 다를 때도 읽히게)
- 흐름도·결정 나무(부록 A 방법 선택 지도, 24강 모형 선택 흐름 등)는 **Mermaid**로 씀. GitHub가 바로 그려 주고 원본이 텍스트라 고치기 쉬움
- 모든 그림은 `book/fig-src/`의 스크립트로 다시 그릴 수 있어야 함

**링크**
- 강 사이 참조는 상대 경로 링크(`[12강](12-lisa.md#조건부-순열)`)로 씀
- 절 앵커는 GitHub의 한글 제목 앵커 규칙을 따름. 제목을 바꾸면 링크가 깨지므로 lint가 GitHub 앵커 생성 규칙으로 모든 링크를 점검함

**lint (`book/tools/`, CI에서 실행)**
- VisionDrill `lint-lessons.ts`를 출발점으로 하되 GitHub 기준으로 규칙을 바꿈
- 머리말·필수 절·순서, 수식 구분자 짝, 표 안의 `|`, 한글 굵게 패턴, 깨진 링크·앵커, 없는 그림·안 쓰는 그림, SVG 규칙, 음슴체 어미, 분량
- 추가: 용어집 이형 사용, 앱 지원 표시와 "해 보기" 종류 일치, expected.json 대조, 원전 절 누락, 이전·다음 링크

**HTML 판 (내려받아 읽는 사람용)**
- 원본은 md, HTML은 **생성물**임. HTML은 손으로 고치지 않고, 파일 맨 위에 "자동 생성됨, 원본은 md" 주석을 넣음
- **단일 파일 HTML**: CSS, 미리 그린 KaTeX 수식(글꼴 포함), SVG 그림을 파일 하나에 모두 넣음. 인터넷 없이 브라우저로 두 번 클릭하면 열림
- 두 종류를 만듦
  - 강별: `book/html/<강 파일명>.html`
  - 책 전체: `book/html/book.html`. 목차 사이드바와 강 사이 링크가 파일 안에서 이어짐. 대부분은 이 파일 하나만 받으면 됨
- md와 달리 렌더러를 직접 고칠 수 있음: 한글 굵게 처리, 목차, 이전·다음 이동, 라이트·다크 모드, 인쇄용 CSS(브라우저 인쇄로 PDF 저장)
- 빌드 스크립트 `book/tools/build-html.mjs` (markdown-it + KaTeX). VisionDrill 렌더러를 출발점으로 함
- **빌드는 GitHub Actions가 함**: `book/**`이 바뀐 커밋이 main에 올라가면 HTML을 다시 만들어 `book/html/`에 커밋함. 사람이 빌드를 잊어 md와 HTML이 어긋나는 일을 막음. 봇은 `book/html/`만 건드림 (로컬 작업 전 `git pull`)
- GitHub는 저장소 안의 HTML을 렌더링하지 않고 소스를 보여 줌. `book/README.md` 맨 위에 **HTML 받는 법**(파일을 열고 다운로드 버튼 → 브라우저로 열기)과 `book.html` 바로가기를 둠

**배포**
- github.com에서 md를 읽거나, HTML을 받아 브라우저로 읽음. GitHub Pages는 쓰지 않음 (HTML이 있으므로 나중에 켜기는 쉬움)
- **내려받기 묶음**: 태그 `book-vX.Y`를 달면 GitHub Actions가 `book/` 폴더(본문, HTML, 그림, 자료)를 zip으로 Release에 올림
- PDF·웹 사이트·앱 내장은 1.0 이후에 필요하면 검토함
- 콘텐츠 라이선스 **CC BY 4.0** (`book/LICENSE.md`), 코드는 MIT 유지
- `CITATION.cff`를 두고, 1.0 공개 때 Zenodo DOI를 받아 인용할 수 있게 함
- 강 끝의 **오류 신고** 링크 → GitHub 이슈 템플릿(책 전용 라벨)

**저장소**
- GeoStat 저장소의 `book/`에 둠. 지금 독자는 GeoStat 사용자이고, expected.json과 엔진 테스트가 같은 CI에서 돌아야 하기 때문임
- 저장소 README에서 책으로 가는 링크를 눈에 띄게 둠
- 책 독자가 앱 사용자보다 넓어지면 별도 저장소로 분리하는 것을 검토함

## 10. 품질 관리와 감수

- 본문의 모든 수치는 스크립트로 산출함. 본문에서 직접 계산하지 않음
- 집필 → 독립 검증 → 사람 검수
  - 독립 검증은 집필하지 않은 별도 에이전트가 맡음: 수치 재계산, 원전 대조(정의·식·기호 관례), 도구 기본값 대조
- 상태: `draft` → `verified` → `reviewed`. README에 부별 진행 현황을 표시함
- 1.0 전에 부별로 외부 감수를 받는 것을 권함. 특히 4부(점 패턴), 5부(지구통계), 10부(베이지안)는 해당 분야 연구자의 감수를 받음. 학문 보급서로서의 신뢰도와 직결됨
